# ADR-0003. Текущий пользователь в лаб. 1 — заголовок `X-User-Id`

**Статус:** принято · **Дата:** 2026-09-24

## Контекст
Аутентификация появляется только в лаб. 3 (JWT + Spring Security), но уже в лаб. 1 нужны проверки владения («чужая персона — 404») и логика, зависящая от текущего пользователя (видимость беседы для клиента, специалиста и администратора).

## Решение
Все сервисы принимают доменный тип `Actor(userId, roles)` из `common`. В веб-слое его подставляет резолвер из `web-common` по заголовку `X-User-Id`; пользователя и роли находит модуль `iam` через SPI `ActorLookup`. Заблокированный или неизвестный пользователь — `401`. Проверки ролей (матрица §3.6) выполняются в сервисах и дают `403`; чужие объекты — `404`.
Регистрация (`POST /users`) в лаб. 1 открыта; в Swagger UI заголовок `X-User-Id` добавлен ко всем операциям, которым нужен актор.

## Последствия
- В лаб. 3 меняется только источник `Actor`: резолвер будет брать его из `SecurityContext`. Подписи сервисов и проверки прав не меняются.
- Заголовок легко подделать — это осознанное упрощение лаб. 1, а не механизм безопасности.
