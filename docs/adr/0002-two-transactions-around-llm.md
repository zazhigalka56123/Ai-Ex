# ADR-0002. Короткие транзакции вокруг вызова LLM; `agent_runs` принадлежит модулю `agent`

**Статус:** принято · **Дата:** 2026-09-24

## Контекст
Генерация ответа — сетевой вызов на 2–20 с. Если держать открытой транзакцию (и соединение из пула в 10 штук) на всё это время, десяток параллельных пользователей положит приложение целиком, включая эндпоинты, которым БД нужна на 3 мс.
Черновик архитектуры (v0.9, §9.3) рисовал вставку в `agent_runs` из транзакции `dialog` — это нарушало бы правило «транзакция не пересекает границу модуля» (§6.4 п. 4) и «схема на модуль».

## Решение
`POST /conversations/{id}/messages` выполняется как последовательность коротких транзакций, ни одна из которых не охватывает сетевой вызов и не выходит за модуль:

1. **TX-A** (`dialog`): сообщение пользователя + счётчики беседы.
2. **run-open** (`agent`): `agent_runs` в статусе `PENDING`.
3. Вызов LLM — **вне транзакций**.
4. **run-close** (`agent`): `SUCCESS` с задержкой и токенами, либо `FAILED`/`TIMEOUT` с кодом ошибки.
5. **TX-B** (`dialog`): ответ персоны со ссылкой `agent_run_id` + счётчики.

Тот же принцип — в пересборке профиля персоны (TX-1b): вызов LLM для характеристики выполняется между транзакциями.

## Последствия
- Если LLM недоступен, сообщение пользователя не теряется, прогон честно помечен `FAILED`/`TIMEOUT`, клиент получает `503` и может повторить.
- Между шагами возможна частичная видимость (сообщение пользователя без ответа) — это корректное состояние беседы.
- В лаб. 4 шаги 2–5 естественно превращаются в сагу на брокере.
