# Архитектура лабораторной №2

Spring Boot 4.0.8, Kotlin 2.2.21, Spring Cloud 2025.1.1, Java 21 и PostgreSQL 17.

## Границы

`account-service` владеет пользователями и ролями. Остальные сервисы получают активного пользователя через Feign и самостоятельно проверяют доступ к своим объектам. Если сервис пользователей недоступен, запрос завершается ошибкой 503.

`persona-service` объединяет персоны и импорт: разбор переписки, статистика и переключение версии профиля образуют один сценарий. Все изменения этих данных остаются в одной базе.

`dialog-service` объединяет беседы и агент: сохраняет сообщения, собирает контекст, обращается к модели и записывает прогоны. Внешний вызов модели выполняется между двумя короткими транзакциями.

`care-service` хранит специалистов, слоты, записи и жалобы. При записи блокируется строка слота; уникальное ограничение защищает от двух одновременных бронирований. Чужие сообщения и персоны запрашиваются через Feign.

`notification-service` хранит уведомления в отдельной базе. SQL выполняется через R2DBC `DatabaseClient`. `event_id` уникален; повторная доставка возвращает уже созданный идентификатор. Авторизация через блокирующий Feign вынесена в `boundedElastic`, запросы R2DBC остаются в реактивной цепочке.

В каждом из пяти сервисов свой PostgreSQL. Межсервисных внешних ключей и общего доступа к таблицам нет. Liquibase применяет только миграции сервиса; таблица уведомлений создаётся реактивным SQL-инициализатором.

## HTTP и конфигурация

Gateway раздаёт статические файлы и направляет `/api/v1` по идентификаторам `lb://...`. Маршрут WebSocket использует `lb:ws://dialog-service` и имеет приоритет перед REST-маршрутом бесед.

Eureka хранит адреса приложений. Feign и Gateway используют Spring Cloud LoadBalancer, адреса предметных сервисов не записаны в коде.

Config Server использует native repository, упакованный из `config-repository`. Общий `application.yml` содержит настройки Eureka, JPA, Feign, Resilience4j и предметной логики. Файлы с именами сервисов содержат их порты, подключения к базам и миграции. Gateway получает оттуда маршруты.

Внутренние endpoints не входят в маршруты Gateway. Сервисы проверяют заголовок `X-Internal-Token`. Эта проверка отделяет внутренние вызовы от публичного API; пользовательские роли проверяются отдельно.

## Вызовы и события

- `persona → account`: текущий пользователь.
- `persona → dialog`: описание характера при сборке профиля.
- `dialog → persona`: владелец, состояние и активный профиль.
- `dialog → care`: доступ специалиста к расшаренной беседе.
- `care → account`: пользователи и профиль специалиста.
- `care → dialog`: видимость сообщений и владение беседой.
- `care → persona`: теги и архивация по решению модератора.
- `notification → account`: активный получатель при чтении уведомлений.

После commit `PersonaArchived` закрывает беседы в `dialog-service`, `ModerationFlagRaised` помечает сообщение, `MessageAutoFlagged` создаёт жалобу в `care-service`. События импорта, готовности персоны, консультаций и разбора жалобы вызывают сервис уведомлений. Вызов полученного события идёт прямо в локальный обработчик, чтобы не создавать цикл пересылки.

Доставка событий синхронная, без брокера и долговременного повторения. Исходная транзакция уже зафиксирована; отказ получателя не может её отменить. Уведомления защищены от повторной доставки по `eventId`.

## Reactor и отказоустойчивость

В `account-service` публичные контроллеры возвращают `Mono`. `Mono.fromCallable(...).subscribeOn(Schedulers.boundedElastic())` выполняет обращение к JPA через транзакционный Spring proxy после подписки. Весь блокирующий сценарий и преобразование ответа выполняются в рабочем потоке.

В `notification-service` контроллеры и доступ к базе используют Reactor. Блокирующий Feign-вызов проверки пользователя выделен в отдельный `Mono` с `boundedElastic`.

Feign обёрнут в Spring Cloud CircuitBreaker с Resilience4j. Ошибки 4xx не считаются отказом зависимости. Транспортные ошибки, ответы 5xx и открытый Circuit Breaker превращаются в `503 SERVICE_UNAVAILABLE`. Проверки доступа при этом не обходятся.

## Тесты

`app` собирает исходные предметные компоненты в общем контексте с профилем `test`, чтобы запускать сценарии первой лабораторной без сети между сервисами. Адаптеры Feign и пересылка событий включаются только в профиле `microservice`.

Отдельные тесты проверяют Reactor + JPA на PostgreSQL, WebFlux + R2DBC, ошибки Feign и отправку событий после commit. `docs/lab2-smoke.sh --outage` проверяет работающие сервисы через Gateway, Config Server и Eureka, затем останавливает сервис пользователей и проверяет открытие и восстановление Circuit Breaker.
