# ЛР3: запуск и защита

Рабочая папка ветки — `app-lab3`. Команды ниже выполняются из неё.

## Запуск

Скопируйте `.env.example` в `.env`. Заполните `JWT_SECRET` случайным значением
из `openssl rand -hex 32`, `BOOTSTRAP_ADMIN_EMAIL` и `BOOTSTRAP_ADMIN_PASSWORD`
(минимум 12 символов, максимум 72 байта UTF-8).

```sh
docker compose up -d --build --wait
```

Swagger: http://localhost:8081/swagger-ui.html. Это порт Gateway на хосте;
внутри Docker Gateway слушает 8080, IAM — 8081.
`GATEWAY_PORT` в `.env` меняет внешний порт. Проект Compose называется `ai-ex-lab3`:
его тома отделены от `ai-ex-lab2`. Для одновременного запуска двух лабораторных
также нужно разделить внешние порты `CORE_DB_PORT`, `IAM_DB_PORT`,
`NOTIFICATION_DB_PORT`, `CONFIG_PORT`, `EUREKA_PORT`.

Первый запуск создаёт супервайзера с ролью ADMIN. Повторный запуск не меняет
его пароль. Старые пользователи из lab2 сохраняются, но без назначенного пароля
войти не могут: миграция ставит маркер отключённого входа `!`, а не общий пароль.
Супервайзер назначает им пароль через PATCH `/api/v1/users/{id}`.

## Что показать в Swagger

1. Выберите `iam`, вызовите POST `/api/v1/auth/login` с email и паролем супервайзера.
2. Скопируйте `accessToken` в **Authorize**. Вводится сам токен, без `Bearer`.
3. POST `/api/v1/users`: создайте пользователя с `email`, `displayName`, `password`.
   Ответ — 201 с `Location`; пароля и хэша в JSON нет.
4. Войдите новым пользователем и замените токен в **Authorize**.
   Создание другого пользователя, даже с `roles: ["ADMIN"]`, возвращает 403.
5. Свой профиль доступен, чужой — 404. Без токена защищённые ручки возвращают 401.
   `X-User-Id` не заменяет токен.
6. Снова авторизуйтесь супервайзером и заблокируйте пользователя. Старый токен
   пользователя больше не даёт доступ к его данным.

В БД `iam.users.password_hash` хранится BCrypt-хэш с солью; JWT содержит UUID,
роли и срок действия, но не пароль. Фактические права и статус берутся из IAM,
поэтому роли в ранее выданном токене не позволяют обойти блокировку.

## Circuit Breaker

Войдите обычным активным пользователем, выберите в Swagger `notifications` и
вызовите GET `/api/v1/notifications`: ожидается 200, в том числе для пустого списка.

```sh
docker compose stop iam-service
```

Несколько раз вызовите ту же ручку с действующим токеном: ожидается **503**.
Notifications продолжает работать, но не может проверить пользователя через IAM.
После минимум пяти учитываемых вызовов и доли ошибок не менее 50% breaker
переходит из CLOSED в OPEN. Он перестаёт вызывать IAM и сразу отклоняет запросы.

```sh
docker compose start iam-service
```

Дождитесь запуска IAM и обновления Eureka, затем снова вызывайте ручку.
После 10 секунд в OPEN очередной запрос допускает пробные вызовы в HALF_OPEN.
Два успешных пробных вызова закрывают breaker; ручка снова отвечает 200.
Одного запуска контейнера для закрытия breaker недостаточно — нужны запросы.

В lab3 метрики `/actuator/metrics/**` внутри Notifications требуют служебный JWT.
Старый анонимный `wget` из инструкции lab2 больше не подходит. Автоматический
smoke-сценарий проверяет и 503, и OPEN/CLOSED, используя служебный токен для метрик.

## Проверки

```sh
./gradlew build :koverVerify :koverHtmlReport
```

Сборка и тесты используют JDK 21. Интеграционные тесты поднимают временные
PostgreSQL через Testcontainers. Для Colima при необходимости:

```sh
export DOCKER_HOST=unix://$HOME/.colima/default/docker.sock
export TESTCONTAINERS_DOCKER_SOCKET_OVERRIDE=/var/run/docker.sock
```

Для сквозного сценария предварительно экспортируйте в окружение значения
`BOOTSTRAP_ADMIN_EMAIL`, `BOOTSTRAP_ADMIN_PASSWORD` и `JWT_SECRET` из `.env`.
Compose читает `.env` автоматически; Python — нет.

```sh
python3 scripts/smoke-lab2.py --resilience
```

Имя скрипта сохранено, но он проверяет актуальную JWT-авторизацию lab3,
пользовательские роли, доставку уведомлений и восстановление зависимостей.
Сценарий останавливает IAM и Notifications и запускает их обратно в `finally`.
