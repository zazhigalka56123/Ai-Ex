# ai-ex («Привет, спишь?»)

Лабораторная работа №2. Основа — `classic-monolith` из первой лабораторной.

Пользователь загружает переписку, создаёт по ней ИИ-персону и общается с ней. В системе также есть запись к психологу, модерация сообщений и уведомления. Сценарии и REST API первой лабораторной сохранены.

## Сервисы

- `account-service` — пользователи и роли, WebFlux (Netty) + Reactor + Spring Data JPA. Сервисный слой отдаёт `Mono`, блокирующие вызовы JPA выполняются в отдельном пуле `jpa` размером с пул соединений.
- `persona-service` — персоны, загрузка и разбор переписки, версии профиля. Своя база со схемами `persona` и `ingest`.
- `dialog-service` — беседы, сообщения, WebSocket, генерация ответов и журнал обращений к модели. Своя база со схемами `dialog` и `agent`.
- `care-service` — специалисты, слоты, консультации, жалобы и справочники. Своя база со схемами `care` и `admin`.
- `notification-service` — уведомления, WebFlux + Reactor + R2DBC. Запись и чтение базы выполняются реактивно; схему создаёт Liquibase; повторная доставка одного `eventId` не создаёт дубликаты.
- `config-server` — общие и отдельные конфигурации из `config-repository`.
- `discovery-server` — Eureka.
- `gateway` — единая точка входа, маршрутизация через Eureka и веб-интерфейс.

Каждый предметный сервис запускается отдельным приложением и подключается только к своей базе. Чужие сущности и репозитории ему недоступны. Общие DTO и интерфейсы лежат в `contracts`, Feign-клиенты — в `http-clients`, общая поддержка Spring MVC — в `web-support`, WebFlux (ошибки, `X-User-Id`, пагинация, внутренний токен) — в `reactive-support`.

`app` оставлен для регрессионных тестов первой лабораторной: он собирает предметные модули в одном тестовом контексте. В Docker Compose используется микросервисная сборка.

## Запуск

Нужен Docker Compose:

```bash
docker compose up -d --build --wait --wait-timeout 600
```

- Интерфейс: http://localhost:8080
- Swagger: http://localhost:8080/swagger-ui.html
- Eureka: http://localhost:8761
- Конфигурация сервиса: http://localhost:8888/persona-service/microservice
- Проверка Gateway: http://localhost:8080/actuator/health

Параметры портов, баз и модели перечислены в `.env.example`. По умолчанию работает локальная заглушка модели; API-ключ для демонстрации не требуется.

Демо-пользователи:

- клиент: `00000000-0000-0000-0000-00000000c001`;
- специалист: `00000000-0000-0000-0000-00000000b001`;
- администратор: `00000000-0000-0000-0000-00000000a001`.

Текущий пользователь передаётся заголовком `X-User-Id`. WebSocket работает по адресу `ws://localhost:8080/api/v1/conversations/{id}/ws?userId={userId}`. Внутренние API закрыты от Gateway и проверяют `X-Internal-Token`; его значение задаёт `AIEX_INTERNAL_TOKEN`.

## Взаимодействие

Feign получает адреса сервисов из Eureka. Например, при создании беседы `dialog-service` проверяет владельца персоны через `persona-service`; при сборке профиля `persona-service` запрашивает описание у `dialog-service`.

Все приложения, кроме самого Config Server, обязательно загружают конфигурацию через `spring.config.import=configserver:...`. В локальных YAML остаются имя приложения, профиль и адрес Config Server. Настройки баз, Eureka, маршрутов и Circuit Breaker находятся в `config-repository`.

Circuit Breaker реализован через Spring Cloud CircuitBreaker и Resilience4j. Использована версия, совместимая с Spring Boot 4, вместо старого Hystrix из ссылки в задании. При отказе зависимости запрос возвращает `503 SERVICE_UNAVAILABLE`. Ошибки предметной области сохраняют свой код и не учитываются как сбои сервиса.

Архивация персоны, флаги модерации и уведомления передаются HTTP-вызовами после фиксации исходной транзакции. Получатель обрабатывает событие локально и не пересылает его обратно. Постоянной очереди и восстановления доставки после падения процесса в этой лабораторной нет.

## Проверка

Для сборки вне Docker нужен JDK 21:

```bash
./gradlew build
bash docs/lab2-smoke.sh
bash docs/lab2-smoke.sh --outage
```

Smoke проверяет удалённую конфигурацию, регистрацию в Eureka и сценарий первой лабораторной через Gateway. Режим `--outage` останавливает `account-service`, проверяет ответы `503`, открытие Circuit Breaker и восстановление после запуска сервиса.

Архитектура и границы сервисов описаны в [docs/architecture.md](docs/architecture.md).
